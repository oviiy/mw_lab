# 聪明钱追踪器（smart-money）— 设计文档

日期：2026-10-15
状态：待审阅

## 1. 目标

做一个有深度、图表丰富、打开即可演示的机构与内部人交易追踪站点，并且能长期维护。核心问题有三个：

1. **基金经理在做什么？** 持仓、调仓、风格，以及跟着他们买有没有用。
2. **一只股票被谁拿着？** 持有人结构、资金流向、拥挤度，以及内部人在买还是在卖。
3. **哪些信号历史上有效？** 内部人集中买入、13F 克隆组合。

### 硬性约束

- **只用公开数据：** SEC EDGAR、OpenFIGI、免费行情。不使用任何雇主的数据、代码或账号。
- **形态与仓库一致：** Python 构建脚本生成数据，前端是纯静态页面，无后端，可直接用 GitHub Pages 托管（参考 `treasury-factors/`）。
- **可复现：** 任何人运行构建脚本，都能从公开源得到相同的数据。仓库只提交计算结果 JSON（行情只保留展示用的周频收盘价），不再分发第三方原始数据。

### 非目标

- 实时数据和盘中更新。
- 用户账号、自选股、提醒推送。
- 投资建议。站点只展示数据和历史统计，页脚有免责声明。
- 空头头寸。13F 不披露空头，界面上要明确说明这一点。

## 2. 数据源

| 数据 | 来源 | 频率 | 说明 |
|---|---|---|---|
| 13F 持仓 | SEC Form 13F Data Sets（`SUBMISSION`、`COVERPAGE`、`INFOTABLE`、`SUMMARYPAGE`、`OTHERMANAGER` 等 TSV） | 季度 | 2013Q2 起。构建脚本从 SEC 数据集索引页解析文件列表，不写死文件名，因为 2024 年起发布周期有变化 |
| 内部人交易 | SEC Insider Transactions Data Sets（`SUBMISSION`、`REPORTINGOWNER`、`NONDERIV_TRANS`、`DERIV_TRANS`、`FOOTNOTES` 等） | 季度批量；当季增量用 EDGAR 每日 Form 4 索引补齐 | 第二阶段接入 |
| 公司信息 | EDGAR `submissions` API、`company_tickers.json` | 按需并缓存 | CIK、名称、SIC 行业、交易所 |
| 流通股本 | EDGAR `companyfacts`（`dei:EntityCommonStockSharesOutstanding`） | 按需并缓存 | 用于计算"13F 机构持股占比" |
| CUSIP → 代码 | OpenFIGI API（免费 key） | 增量 | 结果永久缓存。INFOTABLE 自带的 FIGI 列有值时优先使用 |
| 价格与拆股 | 默认 yfinance（日线复权价 + 拆股记录），备选 Stooq | 每日 | 通过 `PriceSource` 接口接入，可替换 |
| 基金公司信息 | SEC 投资顾问数据（Form ADV Part 1 批量 CSV） | 月度 | 管理规模、成立时间、员工数 |
| 经理简介 | 人工精选，写在配置文件里 | 手工 | 每条事实必须附公开来源 URL |

SEC 访问规范：请求头带 `User-Agent: smart-money <个人邮箱>`，邮箱从 `.env` 读取且不提交到仓库；全局限速不超过 10 次/秒；所有原始下载缓存在 `build/cache/`（已加入 gitignore）。

## 3. 数据处理规则

处理在 `build/` 中用 Python + DuckDB 完成。

### 3.1 13F 清洗

- **持仓主键：** `(filer_cik, period, cusip, put_call)`。期权行（`PUTCALL` 为 PUT 或 CALL）单独存放，不计入股票权重；页面上以名义价值单独展示。
- **金额单位：** 2023-01-03 之前申报的 `VALUE` 以千美元为单位，之后以美元为单位。按**申报日期**统一换算成美元。这是一个已知的坑，必须有单元测试覆盖。
- **修订：** `AMENDMENTTYPE = RESTATEMENT` 时，用修订版替换同期原申报；`NEW HOLDINGS` 时，把修订版的行追加到同期原申报上。同一期取最后生效的版本。
- **多管理人：** 同一 CIK 下多个 `OTHERMANAGER` 的行，按 CUSIP 合并股数。
- **只保留股票类：** 按 `TITLEOFCLASS` 和 OpenFIGI 返回的 `securityType` 过滤，保留普通股、ADR 和 ETF。可转债等其他类型计入"其他"。
- **拆股调整：** 比较相邻两期的股数前，先用拆股记录把上一期股数调整到当期口径。否则拆股会被误判成大幅加仓。

### 3.2 持仓变动分类

按拆股调整后的股数 `s_prev → s_curr` 分类：

| 类别 | 条件 |
|---|---|
| 新建仓 | `s_prev = 0` 且 `s_curr > 0` |
| 清仓 | `s_prev > 0` 且 `s_curr = 0` |
| 加仓 | `s_curr / s_prev − 1 > +2%` |
| 减仓 | `s_curr / s_prev − 1 < −2%` |
| 不变 | 其余情况 |

2% 阈值用来过滤取整和小额噪声，写在配置里，可调。

### 3.3 基金层面指标（每期计算）

- **组合市值：** 当期股票类持仓的申报市值之和。
- **集中度：** 前 10 大持仓权重，以及 HHI = Σ wᵢ²。
- **换手率：** `min(买入额, 卖出额) / 两期平均组合市值`。买卖额按股数变化 × 当期季末价格估算。
- **行业配置：** 按 SIC 映射到 11 个 GICS 风格大类，映射表写在 `build/sic_sectors.csv`。
- **持仓期：** 每只股票连续出现的季度数，取加权平均。

### 3.4 个股层面指标（每期计算，覆盖全部 13F 申报人）

- **持有人数量**，以及相对上期的增减。
- **13F 持股占比：** 全部申报人持股合计 ÷ 流通股本。
- **资金流：** 按"新建、加仓、减仓、清仓"四类，汇总各类申报人的股数变化 × 季末价格。
- **拥挤度评分：** 三项取全市场横截面百分位后等权平均，结果为 0–100。三项分别是：精选经理中的持有人数、13F 持股占比、精选经理组合里的平均权重。

### 3.5 13F 克隆回测

- **再平衡日：** 每份 13F **实际申报日**的下一个交易日。按申报市值权重买入，持有到下一次申报。不用季末日期，以避免前视偏差。
- **对照组一：** 理想化版本，即季末当天就建仓。两者的差值就是"披露延迟的成本"。
- **对照组二：** SPY 全收益。
- **输出：** 累计收益曲线、年化收益、波动率、夏普比率、最大回撤、年化超额收益。
- **覆盖率：** 缺少价格的持仓按权重剔除后重新归一化，页面显示价格覆盖率。覆盖率低于 90% 的季度打上标记。

### 3.6 内部人交易（第二阶段）

- **交易范围：** 只统计非衍生品交易代码 `P`（公开市场买入）和 `S`（公开市场卖出）。期权行权（`M`）、授予（`A`）、扣税（`F`）、赠与（`G`）只在时间线上展示，不进入信号。
- **10b5-1：** 2023-04 起 Form 4 有 10b5-1 勾选字段。勾选的交易单独标记，并从集中买入信号中剔除。
- **集中买入：** 同一公司在 30 个自然日内，有 ≥3 名不同内部人进行 `P` 交易，且合计金额 ≥ 10 万美元。窗口、人数、金额三个参数都可配置。
- **事件研究：** 以 Form 4 **申报日**为第 0 天，因为这是信息公开的日子，而不是交易日。计算第 −20 到 +250 个交易日相对 SPY 的累计超额收益（CAR），给出均值和 95% 自助法置信区间。
- **高管档案：** 每个人的历史 `P` 和 `S` 交易，以及买入后 3、6、12 个月跑赢 SPY 的比例。

## 4. 产品页面

前端用单个 `index.html` 加 hash 路由。所有页面共享顶部搜索框，可以搜经理、股票代码或内部人姓名。

### 4.1 总览 `#/`

- KPI 卡：最新申报季度、已收录的精选经理数、全市场申报人数、13F 总市值。
- 本季度最受追捧和最被抛售的股票：按精选经理的净新建仓数排序，横向条形图。
- 拥挤度前 20 名：气泡图，横轴是持有人数，纵轴是持股占比，气泡大小是总市值。
- 精选经理行业资金流：桑基图，从行业流向行业。
- 内部人集中买入榜（第二阶段）。

### 4.2 基金经理档案 `#/manager/<cik>`

- **档案卡：** 经理姓名、公司、风格标签、所在城市、成立年份、13F 市值、Form ADV 管理规模（Form ADV 推迟到第二阶段接入，第一阶段只显示 13F 市值），以及带来源链接的简介。头像使用首字母徽章，不使用照片，以规避版权问题。
- **持仓矩形树图：** 按行业分组，颜色表示本季度的变动类别。
- **季度变动表：** 新建、加仓、减仓、清仓四个分栏，显示股数变化、金额和权重变化。
- **持仓演变动画：** 前 15 大持仓的赛跑条形图，可以逐季播放。
- **行业配置：** 随时间变化的堆叠面积图。
- **风格指标：** 集中度、换手率、持仓期的时间序列。
- **克隆回测：** 实际申报日版本、理想化版本、SPY 三条累计曲线，下方是指标表。
- **相似经理：** 按当期持仓权重的余弦相似度，列出前 5 名。

### 4.3 个股透视 `#/stock/<ticker>`

- **头部：** 名称、行业、价格走势，内部人买卖点叠加在价格上（第二阶段）。
- **持有人时间线：** 持有人数（柱）和 13F 持股占比（线）。
- **本季度资金流：** 桑基图，从四类变动（新建、加仓、减仓、清仓）流向这只股票，并按精选经理和其他申报人拆分。
- **精选经理持仓表：** 股数、权重、本季度变动、首次买入的季度。
- **拥挤度：** 仪表盘加历史曲线。

### 4.4 内部人雷达 `#/insiders`、`#/insider/<cik>`（第二阶段）

- **集中买入事件流：** 按日期排列，卡片显示公司、人数、金额，以及之后的收益。
- **个人档案：** 职务、在职公司、交易时间线、胜率。
- **事件研究图：** CAR 曲线加置信带。按公司市值和内部人职务分组（CEO/CFO vs 董事 vs 10% 大股东）。

### 4.5 关系网络 `#/network`（第三阶段）

- **经理网络图：** 节点是经理，边的权重是持仓重叠度，阈值可调。
- **共同持有分析：** 选一只股票，高亮所有持有它的经理，以及这些经理之间的连接。

### 4.6 信号实验室与方法 `#/lab`、`#/methods`

- **信号实验室（第三阶段）：** 精选经理的克隆组合排行榜、等权"共识组合"（被 ≥5 位精选经理持有）的回测、集中买入事件研究汇总。
- **方法页（第一阶段起就有）：** 数据源、处理规则（即第 3 节的人话版）、CUSIP 映射覆盖率、价格覆盖率、已知局限、免责声明。

### 数据体积预算

`data/` 总计不超过 50 MB。单个经理 JSON 不超过 300 KB，单只股票 JSON 不超过 100 KB。

股票页只为持有人数排名前 1,500 的股票，加上精选经理持有过的全部股票生成文件。其他股票在搜索中显示"未收录"。

### 前端选型

选择原生 JS + ECharts 5（CDN），不引入构建步骤。ECharts 自带矩形树图、桑基图、关系图和时间轴动画，比仓库里其他项目用的 Plotly 更适合这里。

视觉沿用仓库现有项目（execution-tca）的浅色配色和字体：Inter、JetBrains Mono、Source Serif 4。具体视觉细节在实现阶段用 frontend-design 把关。

### 自动更新（第四阶段）

- GitHub Action 每天运行 `--stage form4,prices,export`，每季度 13F 数据集发布后运行全量构建，然后自动提交 `data/`。
- SEC 联系邮箱存放在仓库 secret 里。

## 6. 错误处理

- **数据格式变化：** 构建时校验 SEC TSV 的列名和类型。不匹配就**直接失败**并打印差异，不静默跳过。
- **CUSIP 映射：** 未映射成功的 CUSIP 写入 `build/reports/unmapped.csv`。覆盖率按市值加权，写进 `meta.json`，并在方法页展示。
- **网络错误：** 网络请求重试 3 次，采用指数退避；遇到 429/403 时整体降速。
- **前端：** JSON 加载失败时显示错误卡片，不白屏。缺数据的图表显示"暂无数据"并说明原因。

## 9. 风险与已知局限

- **13F 本身的局限：** 只有多头、有 45 天延迟、不含空头和大部分非美股票，期权按名义价值申报。这些都会在方法页说明。
- **幸存者偏差：** 免费价格源可能缺少已退市股票，会导致回测收益偏高。需要统计受影响的权重并在页面上展示。
- **数据源稳定性：** yfinance 和 Stooq 不是官方数据源，可能失效。`PriceSource` 接口保证可以更换，比如改用付费的 EODHD 或 Tiingo。
- **经理简介：** 简介容易混入错误或过时的信息。因此只写有来源的事实，每条附 URL，不做主观评价。
- **合规：** 不使用任何雇主资源；SEC 数据属于公有领域；OpenFIGI 遵守其使用条款；行情数据只提交计算结果和展示所需的周频收盘价，不提交日频原始价格文件。
